# 验收演示清单

验收按需求九节的演示顺序推进，每项含操作与预期。自动化可运行 tools/demo_test.ps1 覆盖前四项，场景 5 与 6 在管理端手工验证，场景 7 与 8 为阶段 B 增强，人工演示流程见记忆 15_演示流程。

## 场景 1 注册登录、会员与改密找回
1. 注册：姓名学号邮箱账号密码，重复账号或学号被拒。
2. 登录返回 token，未带 token 访问受保护接口返回 401。
3. 修改密码：旧密码错误被拒，改后新密码可登录。
4. 会员设置：管理端把用户设为会员后，可预约与浏览对内琴房，见场景 2。
5. 找回密码：邮件通道占位中，演示以管理员重置密码代替，待管理端接口后走通。

## 场景 2 琴房浏览与搜索，对内对外区分
1. 普通用户琴房列表仅对外 3 间，对内详情与预约返回 403。
2. 会员与管理可见 5 间含对内，关键字搜索按琴房名过滤。
3. 琴房详情含乐器明细与注意事项。

## 场景 3 预约成功与冲突拒绝
1. 成功预约：对外琴房未来日期、窗口内、按 30 分钟对齐、4 小时内。
2. 冲突拒绝：同房同日重叠时段返回 409。
3. 校验拦截：超提前天数、超时长、非会员约对内、信用暂停均拒绝并提示。
4. 每周次数上限生效：本周第 4 次创建被拒。

## 场景 4 退约后空出提醒生效
1. 账号 A 预约时段被占后，账号 B 无法约同段。
2. B 对同段设置关注。
3. A 退约，时段立即释放，B 收到站内空出提醒，先约先得。
4. B 的该条关注状态变 notified。

## 场景 5 减分与暂停服务，依赖管理端
1. 管理员人工减分，信用低于阈值后用户预约被拒。
2. 每日自然恢复任务加回信用至上限，流水可查。
3. 恢复至阈值以上预约恢复。

## 场景 6 管理端规则参数修改即时生效
1. 管理端改最小单位、最大时长、提前天数或周次数任一参数。
2. 保存后新规则立即生效，前端提示随之变化，无需重启。
3. 再故意把最小单位改为 0，或把信用暂停阈值改到高于信用上限，保存被拒并提示应在 5 到 240 之间或阈值不能高于信用上限，库中参数保持不变。

## 场景 7 活跃度排行榜
1. 打开用户端排行榜页，切周榜与月榜，分值与排名随登录、预约、关注、反馈累计，退约计负分。
2. 昵称脱敏展示，本人排名与数据更新时间正确。
3. 管理员账号不出现在榜单中。

## 场景 8 临近取消风控
1. 预约当天临近开始的时段并立即退约，重复三次，前两次返回计数 1 与 2。
2. 第三次退约后进入临时限制，风控状态返回解除时间，计数展示为阈值次数。
3. 第四次创建预约返回 409 与解除时间，琴房详情页展示提示并禁用预约按钮。
4. 演示前注意：仅当预约开始时间距当前不足 risk.nearCancelWindowMin 分钟时退约才计临近取消，凌晨或时段较早时需先把该参数临时调大，演示后复位 120。

## 场景 9 退约提醒异步与降级
1. 正常态：A 预约某时段，B 关注同段，A 退约；打开 B 的消息中心，数秒内收到空出提醒；管理端事件概览显示 mode 为 async、outbox 已投递计数增加、事件计数含 booking.cancelled。
2. 降级态：管理员停掉 RabbitMQ 服务后重启后端，重复上述退约流程；提醒仍即时送达，概览显示 mode 为 degraded、brokerReachable 为 false、outbox 与 dlq 返回 null 且页面只提示不报错。
3. 恢复态：重新启动 RabbitMQ 服务，等一个重投间隔后概览回到 async，本地消息表中的 pending 记录被投递或按上限停止。
4. 演示前注意：停启服务需管理员权限，用 net stop RabbitMQ 与 net start RabbitMQ；演示结束保持服务运行并清理演示数据。
