# 刘善宁个人参与部分汇报稿

> 口头汇报用稿。代码位置均以当前 `feature/liushanning-user-web` 分支为准；现场可按“文件：函数/关键字”搜索。

## 一、Redis 接入前：v1 用户端（中期汇报）

我的主要工作是完成用户端 Vue 页面、接口封装和预约主流程，保证用户可以从登录进入系统，完成“查琴房—看空闲—预约/关注—查看结果”的闭环。

1. **用户端工程与登录鉴权**
   - 使用 Vue 3、Vite、Element Plus 搭建用户端页面框架，统一顶部导航、侧边栏、消息未读数和退出登录。
   - 实现登录、注册、忘记密码、重置密码、个人资料和修改密码；路由拦截未登录访问。
   - 代码位置：`frontend/user-web/src/App.vue`（`refreshUnread`、`handleCommand`）；`frontend/user-web/src/router/index.js`（`routes`、`router.beforeEach`）；`frontend/user-web/src/views/Login.vue`（`submitLogin`、`submitRegister`、`submitForgot`、`submitReset`）；`frontend/user-web/src/views/Profile.vue`（`save`）；`frontend/user-web/src/api/auth.js`。

2. **统一请求处理**
   - 封装所有用户端 REST 请求，自动携带 token，统一解析后端返回值；遇到 401 自动清理登录状态并跳转登录页，同时把网络错误转换为可显示的提示。
   - 代码位置：`frontend/user-web/src/utils/request.js`（`request` 拦截器、`clearExpiredLogin`、`ApiError`）。

3. **琴房浏览、详情和空闲时段查询**
   - 支持按名称、琴房类型筛选和分页；详情页展示琴房信息、乐器、开放时间及指定日期的空闲区间。
   - 将后端分钟数转换为时分格式，并按规则限制可预约日期和时间粒度。
   - 代码位置：`frontend/user-web/src/views/Rooms.vue`（`load`、`search`、`reset`）；`frontend/user-web/src/views/RoomDetail.vue`（`load`、`loadFree`、`starts`/`ends`、`disableDate`）；`frontend/user-web/src/api/rooms.js`；`frontend/user-web/src/utils/time.js`（`minuteToTime`、`timeRange`、`todayString`）。

4. **预约、退约与冲突反馈**
   - 在提交前校验时间区间是否有效且位于空闲区间内；提交时显示加载状态，成功后跳转“我的预约”，后端冲突时给出明确提示。
   - “我的预约”支持按状态筛选、分页、退约确认和结果刷新。
   - 代码位置：`frontend/user-web/src/views/RoomDetail.vue`（`valid`、`submitBooking`）；`frontend/user-web/src/views/Bookings.vue`（`load`、`cancel`）；`frontend/user-web/src/api/bookings.js`。

5. **关注和空出提醒查看**
   - 对无空闲时段提供关注入口；“我的关注”支持状态筛选、取消关注和确认提示，配合后端退约后的站内提醒。
   - 代码位置：`frontend/user-web/src/views/RoomDetail.vue`（`submitWatch`）；`frontend/user-web/src/views/Watches.vue`（`load`、`remove`）；`frontend/user-web/src/api/watches.js`。

6. **首页、消息和反馈功能**
   - 首页展示轮播图、公告和快捷入口；消息中心支持未读筛选、分页和标记已读；反馈页支持提交反馈并查看处理状态。
   - 代码位置：`frontend/user-web/src/views/Home.vue`（`onMounted` 数据加载）；`frontend/user-web/src/views/Messages.vue`（`load`、`read`）；`frontend/user-web/src/views/Feedback.vue`（`load`、`submit`）；`frontend/user-web/src/api/content.js`、`messages.js`、`feedback.js`。

## 二、Redis 接入后：阶段 A 配合与阶段 B 功能

Redis 由后端负责接入和缓存失效，我负责用户端适配增强结果，确保缓存、限流等后端能力在页面上有明确反馈，同时继续保持 Redis 未启动时 v1 主流程可用。

1. **阶段 A：缓存/限流结果的前端适配**
   - 列表接口直接使用后端返回的 `roomName`，减少前端额外查询；列表加载增加 loading 和空态。
   - 预约、取消关注按钮增加防重复提交；识别 429 限流响应并提示“操作过于频繁，请稍后再试”。
   - 代码位置：`frontend/user-web/src/views/Bookings.vue`（`roomName` 展示、`cancellingId`、`cancel`）；`frontend/user-web/src/views/Watches.vue`（`removingId`、`remove`）；`frontend/user-web/src/views/RoomDetail.vue`（`operationError`、`submitBooking`、`submitWatch`）。

2. **阶段 B：活跃度排行榜页面**
   - 增加周榜/月榜切换、我的排名、排行榜表格、加载状态和无数据提示；接口异常时降级为友好提示。
   - 通过环境变量开关控制，后端接口未就绪时只显示预留说明，不影响 v1 页面。
   - 代码位置：`frontend/user-web/src/views/ActivityRanking.vue`（`enabled`、`load`、`period`）；`frontend/user-web/src/api/ranking.js`（`getActivityRanking`）；`frontend/user-web/src/App.vue`（`rankingEnabled` 和菜单项）；`frontend/user-web/.env.example`（`VITE_ACTIVITY_RANKING_ENABLED`）。

3. **阶段 B：临近取消风控提示**
   - 预约详情页按开关请求用户风控状态；达到阈值时展示原因、临时限制截止时间和取消次数，并禁用预约按钮。
   - 如果提交预约返回风控冲突，也会即时刷新页面状态；接口不可用时静默降级，不阻断正常预约流程。
   - 代码位置：`frontend/user-web/src/views/RoomDetail.vue`（`riskEnabled`、`risk`、`applyRiskStatus`、`loadRisk`、`submitBooking`）；`frontend/user-web/src/api/risk.js`（`getNearCancelRisk`）；`frontend/user-web/.env.example`（`VITE_NEAR_CANCEL_RISK_ENABLED`）。

4. **阶段 B 接口评审协作**
   - 参与排行榜和临近取消风控接口评审，按冻结的 v0.5 契约完成用户端字段和错误状态适配。
   - 记录位置：`docs/接口评审_阶段B.md`、`docs/接口清单.md`。

## 汇报收束

前一阶段我完成了用户端 v1 的核心使用闭环；Redis 接入后，我把缓存/限流等后端增强能力转化为前端可感知的加载、防重复提交和错误提示，并完成了可开关的排行榜和临近取消风控页面，增强功能关闭时不影响原有预约主链路。
