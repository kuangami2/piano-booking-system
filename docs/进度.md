## 四、问题与解决，择要
1. 并发兜底：booking 唯一约束初版缺并发保护，先后尝试并入 status 均失败，最终以生成列 active_slot 只约束进行中预约解决。
2. 写库坑：全局 update-strategy 为 IGNORED 时空实体 updateById 会把未设字段置空，改用 LambdaUpdateWrapper 仅更新目标列。
3. 注入坑：同类型多 Bean 时 @Resource 按字段名匹配，注入 StringRedisTemplate 须显式指定名称。
4. 性能坑：MyBatis 标准输出 SQL 日志使 100 并发 P50 达 3.3 秒，改 Slf4jImpl 并降级 mapper 日志后 P50 9.2 毫秒。
5. 消息坑：全局消息转换器会被监听容器抢先用于转换，重投带 x-death 的消息会被直接丢弃；死信重投用 basicGet 取出后必须显式确认。
6. 完整清单见本机记忆 1_房间预约系统 的 16_故障排查.md。
