# 阶段 B 接口评审草案

状态：待评审，2026-09-09。评审通过后接口清单升 v0.5 并冻结，冻结前不得提交相关实现。

## 一、评审范围
1. GET /api/rankings/activity，用户端活跃度排行榜。
2. GET /api/risk/near-cancel，当前用户临近取消风控状态。
3. 预约创建命中风控时的响应扩展。
4. 事件通道为内部实现，不暴露 HTTP 接口。
5. 请求级幂等请求头 X-Idempotency-Key 是否纳入本期。
6. 阶段归属：排行榜与临近取消风控同属阶段 B，阶段 C 只做 MQ 事件总线与提醒异步化，本次评审不含阶段 C 内容。

## 二、待确认要点与建议方案
1. 排行榜分页：建议 period 取 week 或 month，page 与 size 默认 1 与 20，返回 list 含 rank、userId、name、score，另返回 me 本人排名与分数、updatedAt 更新时间；分数相同按 userId 升序稳定排序。备选只返回前 50 名不分页。
2. 隐私字段：建议只返回昵称脱敏与排名分数，不返回邮箱与 openid，本人可查看自己的完整分数。备选只返回排名与分数，不显示身份信息。
3. 风控参数来源：建议复用 /api/admin/rules 键值，新增 risk.nearCancelWindowMin、risk.nearCancelThreshold、risk.blacklistDurationMin，不新增管理端接口。备选新增独立管理接口。
4. 风控命中响应：建议预约创建返回 code 409，data 含 until 解除时间、reason 原因与 nearCancelCount 次数，沿用统一 Result。备选新增独立业务码。
5. 计分事件与权重：建议六类事件登录、预约、退约、关注、消息已读、反馈，权重键 activity.weight.*，默认值 1、5、负 3、2、1、2，退约计负分。
6. 一致性口径：排行榜最终一致，异步更新并返回 updatedAt；风控命中判断强一致，写预约前同步检查。
7. 幂等：建议本期不实现 X-Idempotency-Key，仅留档，避免范围膨胀。
8. 限流叠加：排行榜与风控状态接口纳入限流，建议每分钟 30 次，独立于预约与关注的每分钟 10 次。

## 三、冻结流程
1. 组员逐项回复同意或修改意见，刘善宁与孙业腾各自确认涉及页面与统计的口径。
2. 组长汇总结论，更新 docs/接口清单.md 十七节为已冻结 v0.5，并写明冻结日期。
3. 冻结后进入实现：后端由组长实现，用户端排行榜页面刘善宁，管理端风控参数页孙业腾。

## 四、影响面
1. 用户端新增排行榜入口与风控提示，不改变现有预约主流程。
2. 管理端规则页新增三项风控参数，复用现有保存接口。
3. 数据库不新增表，事件与分数按阶段 B 方案选择进程内事件或 Redis 存储。
