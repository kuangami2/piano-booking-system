# 房间预约系统：需求说明

状态：v1.1 已实现并验收。第一至十一节为当前版本需求，均已落地；未实现需求集中在第十二节。

## 一、项目概述
琴房预约系统，面向少房间高自由度预约。用户端与管理端现阶段均为 Web，后端 Spring Boot，数据库 MySQL。接口前后端分离且无状态鉴权，为后续迁移微信小程序预留空间。

## 二、用户角色与注册
1. 普通用户：姓名、学号、邮箱注册，自定义密码，提供修改途径。
2. 会员：在普通用户基础上提升优先级，可预约对内琴房。
3. 管理员：Web 后台，管理琴房、规则、用户与信用。
4. 密码找回与重置：邮箱自助找回，令牌 30 分钟一次性并作废旧令牌；已登录用户改密页提供忘记原密码入口转入重置；管理员重置权限保留为邮件通道不可用时的兜底。
5. 注册唯一性与格式：登录名、学号、邮箱三者唯一，学号与邮箱有唯一索引兜底；登录名 4 至 20 位字母开头可含字母数字下划线或 10 位学号，密码 8 至 20 位含字母与数字不含空格，姓名 2 至 20 位汉字或字母，学号 10 位数字，邮箱标准格式；前后端双重校验且以后端为准，错误具体到字段。
6. 登录态失效：token 以密码 hash 加签，改密即失效；接口返回未登录或失效时两端均清登录态并回到登录页。
7. 用户表预留微信 openid 字段，后续小程序迁移时可绑定。

## 三、场地管理
1. 琴房分对内与对外两类，会员可预约对内琴房，普通用户预约对外琴房。
2. 琴房数量暂定 5 间，后续可增加。
3. 每间琴房有详情说明，含乐器明细与注意事项，乐器独立成表一对多。
4. 每间琴房由管理端指定可约时间窗，如 6 点至 22 点。

## 四、预约规则，管理端参数化配置
1. 参数与默认值：时间粒度 30min、单次时长上限 4h、提前预约天数上限 7d、每周预约次数上限 3、每周退约次数上限 2。
2. 同一房间同一时段不允许重复预约，冲突即拒绝。
3. 随退随约，退约立即释放时段。
4. 无固定时段，可约时间窗内自由选择连续区间。
5. 时间推进自动化：预约按日期自然过期转已完成，可约窗口每日顺延，每周次数按自然周滚动，历史记录保留原表。
6. 周次数为实时统计而非计数器，特殊放行以额外配额实现，见第十二节。
7. 预约提交的每种拦截情况都给出明确提示，不得静默返回；预约记录默认最新创建靠前。

## 五、空出提醒与通知
1. 用户想约的时段被占用时，可对该时段设置关注。
2. 时段被退约释放后通过站内提醒通知关注者，先约先得，不设预留；提醒匹配排除退约人本人。
3. 退约成功后本人收到确认消息；管理端取消预约时给预约人发取消通知并说明来源，同时提醒关注者。
4. 退约提醒经事件总线异步投递，消息队列不可用时同步降级，保证送达且不重复；消息支持单条已读与一键全部已读。
5. 通知做消息通道抽象，后续接小程序订阅消息时替换通道即可。

## 六、信用体系与风控
1. 用户有随时间自然恢复的信用分，初始值与上限由管理端指定。
2. 仅人工减分：用户联系管理员反馈，线下核实后减分，系统不做举报功能。
3. 信用分低于阈值暂停预约服务。
4. 减分与恢复参数化，记录信用变更流水。
5. 临近取消风控：退约时刻距预约开始不足窗口分钟计一次，达阈值临时限制预约，命中返回 409 与解除时间。
6. 活跃度计分：登录、预约、退约、关注、消息已读与反馈按权重累计，退约计负分，排行榜周榜月榜滚动且只统计普通用户与会员。

## 七、功能模块
用户端 Web：
1. 注册登录，姓名学号邮箱，自定义密码，找回与修改。
2. 首页轮播图片与系统公告。
3. 琴房列表与详情，含乐器明细，区分对内对外，支持搜索。
4. 琴房预约，冲突提示与空出提醒设置。
5. 我的预约、我的关注、消息中心、反馈与个人中心。
6. 活跃度排行榜，周榜与月榜。

管理端 Web：
1. 首页统计分析，琴房使用率与预约概况。
2. 用户管理，含会员设置、密码重置与信用操作。
3. 琴房管理，含内外类型、乐器明细与可约时间窗。
4. 预约管理，按日期、琴房、用户与状态查询并取消。
5. 规则参数配置，按预约、信用、活跃度与风控四组。
6. 信用管理、内容管理、反馈处理。
7. 事件与投递概览，展示运行模式、本地消息表计数与死信状态。

## 八、查询展示
1. 我的预约按状态筛选，默认最新创建靠前。
2. 琴房空闲查询，按日期与房间。
3. 管理端按日期查看预约情况，列表默认最新创建靠前。

## 九、质量与并发保障
1. 缓存一致性：热点读走缓存，写后主动失效，管理端改动秒级可见；前缀失效用 SCAN 避免阻塞 Redis。
2. 限流：登录后按用户、未登录按来源 IP 计数，防止高频尝试与暴力破解。
3. 缓存击穿保护：热点键失效瞬间并发回源合并为一次查询。
4. 前端节流：列表刷新与日期切换等高频交互补充节流。
5. 并发压测：50 与 100 并发验证错误率与响应时间，确认无连接耗尽、限流误伤与雪崩；实测 100 并发 P50 9.2 毫秒，吞吐 1867 QPS。
6. 自动化测试：后端单元测试与 JaCoCo 覆盖率报告、端到端验收脚本、并发压测脚本，见 测试与覆盖率.md。

## 十、验收演示重点，按序演示
1. 注册登录、会员与改密找回。
2. 琴房浏览与搜索，对内对外区分。
3. 预约成功与冲突拒绝。
4. 退约后空出提醒生效，预约人收到退约确认。
5. 减分与暂停服务。
6. 管理端规则参数修改即时生效。
7. 活跃度排行榜与临近取消风控。
8. 退约提醒异步投递与 MQ 不可用时的同步降级。
9. 管理端取消预约通知预约人，消息中心一键已读，预约拦截给出明确提示。

## 十一、部署与迁移预留
1. 本地部署为主，用户端与管理端 Web 本机可跑；后端接口无状态化。
2. 接口统一 REST 加 JWT，不依赖 Web 会话。
3. 用户表含微信 openid，登录抽象可插微信授权。
4. 通知抽象消息通道，可替换为订阅消息。
5. 前端页面与接口分离，小程序端复用同一接口。

## 十二、未实现需求
### （1）新公告弹窗提醒
用户端登录或进入首页时，若存在未读公告则弹窗提示，已读后不再重复弹出。
### （2）用户周配额管理
管理端为指定用户设置本周额外预约与退约次数，用于特殊情况放行；周次数为实时统计而非计数器，故采用额外配额而非清零。详见 接口评审_阶段D.md。
### （3）可约区间变更与预约同步通知
管理端修改琴房时间窗或临时关闭指定日期时段时，先预览受影响预约，确认后取消并通知用户，关闭期间禁止新预约。详见 接口评审_阶段D.md。
### （4）轮播图裁剪上传接入
裁剪上传组件已封装于双端 src/components/ImageCropper.vue，比例 21:9、输出 1260×540；管理端接入轮播管理，用户端容器锁定 aspect-ratio 21:9 并让右列跟随高度。
### （5）用户端头像上传
个人中心增加头像上传，复用裁剪组件，比例 1:1、输出 320×320；后端需 sys_user 增加 avatar 字段与登录用户可用的上传接口，并入阶段 D 草案。
