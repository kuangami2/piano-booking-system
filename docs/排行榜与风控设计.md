# 排行榜与风控设计

阶段 B 实现说明，2026-09-10。契约见 docs/接口清单.md v0.5 十七节，评审记录见 docs/接口评审_阶段B.md。

## 一、接口
1. GET /api/rankings/activity，参数 period 取 week 或 month，page 与 size 默认 1 与 20，size 上限 50，返回 list、me 与 updatedAt。
2. GET /api/risk/near-cancel，返回 active、until、reason、nearCancelCount，仅本人。
3. 预约创建命中风控返回 code 409，data 含 until、reason、nearCancelCount。
4. 两接口按用户每分钟 30 次限流，与预约创建、关注的每分钟 10 次相互独立。

## 二、计分设计
1. 事件与权重：登录 1、预约 5、退约负 3、关注 2、消息已读 1、反馈 2，键为 activity.weight.*，由管理端规则页维护。
2. 存储：Redis ZSET，键 rr:rank:activity:week:{年-周} 与 rr:rank:activity:month:{年-月}，成员为用户 ID，分值累计；周键 14 天过期，月键 62 天过期，按周期自然滚动，不做全量重算。
3. 计分点：登录成功、预约创建成功、退约成功、关注新增、消息已读、反馈提交。
4. 一致性与更新：排行榜最终一致，响应返回 updatedAt；隐私按评审结论只返回脱敏昵称，不返回邮箱与学号。

## 三、风控设计
1. 判定：退约时若距预约开始时间小于 risk.nearCancelWindowMin 分钟，计一次临近取消。
2. 计数与限制：计数键 rr:risk:near-cancel:count:{userId} 按黑名单时长过期；达到 risk.nearCancelThreshold 次时写入黑名单集合 rr:risk:near-cancel:blacklist 与到期键 rr:risk:near-cancel:expire:{userId}，并重置计数。
3. 拦截：创建预约前同步检查黑名单，命中返回 409 与解除时间，属强一致判断。
4. 参数：risk.nearCancelWindowMin 默认 120、risk.nearCancelThreshold 默认 3、risk.blacklistDurationMin 默认 60，均复用 /api/admin/rules 维护。

## 四、降级与开关
1. 开关：app.enhance.activity-enabled 与 app.enhance.risk-enabled，默认开启。
2. Redis 不可用时排行榜计分与风控计数回退进程内实现并暂停重试 30 秒，单实例演示可用，重启后分值清零。
3. 风控与计分失败不阻断预约创建、冲突检测与退约状态更新等主链路事务。
