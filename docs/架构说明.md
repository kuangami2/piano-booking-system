# 房间预约系统：架构与设计

一、技术栈决策，2026-09-06 归档，Web 双端
1. 后端：Spring Boot 3.5 加 MyBatis-Plus 3.5.9 加 MySQL，以 3+3 脚手架融合管理平台为骨架，jakarta 体系。
2. 用户端与管理端均为 Web，用户端 Vue3 加 Element Plus 或独立模板待定，管理端 Vue3 加 Element Plus。
3. 小程序迁移预留：接口统一 REST 加 JWT 无状态，用户表含微信 openid，登录与通知做抽象，前端与接口分离。
4. 2+2 脚手架与参考项目 RoomReservationSystem 为 Boot 2.5 旧栈，仅作业务参考不采用。
5. 并发方案：预约事务内先读规则快照再查冲突再写，规则缓存修改时刷新；双人同时约同一时段用房间加日期行锁加唯一兜底。

二、分层设计
1. controller 路由层，参数校验，调 service。
2. service 业务层，预约规则校验与冲突检测，信用与提醒逻辑。
3. mapper 数据层，MyBatis-Plus 加 XML。
4. entity 加 dto 加 common，统一 Result，JWT 拦截，全局异常。
5. 用户端与管理端各自前端工程，共用后端接口，按角色接口分组。

三、数据模型草案，待需求定稿后更新
1. sys_user 用户，姓名学号，角色，信用分，预留微信 openid。
2. room 琴房，说明与可约时间窗。
3. room_instrument 乐器，一对多。
4. booking 预约，用户房间日期区间状态。
5. watch 关注，空出提醒。
6. credit_log 信用流水。
7. feedback 反馈举报。
8. rule_config 规则参数。
9. notice 公告，banner 轮播，message 站内提醒。
