# 房间预约系统：架构说明

状态：2026-09-17。只记录当前版本架构，技术栈、分层、数据模型与关键设计。

## 一、技术栈
1. 后端：Spring Boot 3.5、MyBatis-Plus 3.5.9、MySQL 8、Redis、RabbitMQ 4.3.6，jakarta 体系，以管理平台脚手架为骨架，该脚手架提供 Spring Boot 分层骨架、Vue3 前端模板、双角色 JWT 鉴权与统一返回。
2. 前端：用户端与管理端为独立 Vue3 加 Vite 加 Element Plus 工程，开发端口 5173 与 5174。
3. 小程序迁移预留：接口统一 REST 加 JWT 无状态，用户表含微信 openid，登录与通知做抽象，前端与接口分离。
4. 并发方案：预约事务内先读规则快照再查冲突再写；写路径先对房间行加锁串行化同房并发，再查区间重叠后插入；生成列 active_slot 唯一索引兜底同日同起点的进行中预约。

## 二、分层设计
1. controller 路由层，参数校验并调用 service。
2. service 业务层，预约规则与冲突检测、信用与提醒、缓存限流计分风控、事件发布与消费。
3. mapper 数据层，MyBatis-Plus 加 XML。
4. entity 加 dto 加 common，统一 Result、JWT 拦截与全局异常。
5. event 事件信封与载荷、listener 消费者、task 定时任务。
6. 用户端与管理端各自前端工程，共用后端接口，按角色接口分组。

## 三、数据模型，14 表
1. sys_user：姓名学号邮箱、role、is_member、credit、openid 预留，学号与邮箱唯一。
2. room：room_type 区分内外，open_start 与 open_end 为可约窗分钟。
3. instrument：乐器表，与 room 一对多。
4. rule_config：规则参数键值表，修改后刷新缓存即时生效。
5. booking：book_date 加 start_min 与 end_min 存区间，状态 booked、cancelled、finished，生成列唯一约束兜底并发。
6. watch：关注表，uk_watch_slot 防重复关注。
7. credit_log：信用流水表，含经办管理员。
8. feedback：反馈表。
9. message：站内消息表，通道抽象。
10. notice：公告表。
11. banner：轮播图表。
12. password_reset：找回令牌表，30 分钟一次性。
13. event_outbox：本地消息表，事件与业务同事务落库，提交后投递，失败重投并记录来源。
14. processed_event：消费幂等表，以 eventId 为主键。

## 四、接口与页面
接口契约见 接口清单.md v0.8，页面清单见 页面清单.md v0.3，均按角色分组，接口与页面分离便于小程序复用。

## 五、关键设计与降级
1. 缓存：热点读走缓存，写后主动失效，前缀失效用 SCAN 游标分批；未命中共用键级单飞合并回源，Redis 异常回退进程内。
2. 限流：登录后按用户、未登录按来源 IP 固定窗口计数，Redis 优先，异常回退进程内。
3. 事件链路：业务事务内写 event_outbox，提交后投递；消费者以 processed_event 幂等、手动确认，业务异常进死信队列并按次数重投；broker 不可达或开关关闭时同步降级为直接提醒。
4. 转换器边界：JSON 转换器只作用于发布端，消费者保持原始消息由业务代码解析，避免转换失败被容器拦截并丢弃。
5. 排行榜与风控：周月 ZSET 按周期滚动，Redis 不可用回退进程内；排行榜最终一致，风控在创建预约前强一致拦截。
6. 提醒复用：空出提醒与取消确认统一在 VacancyNotifyService，异步消费者与同步降级共用同一实现。
