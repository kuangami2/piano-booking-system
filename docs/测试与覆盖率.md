# 测试与覆盖率

房间预约系统后端测试基建，2026-09-15 首次建立，配套 docs/进度.md 与 docs/代码仓实现清单.md。

## 一、测试栈与命令
1. 依赖：spring-boot-starter-test，范围 scope=test，含 JUnit 5、Mockito 与 AssertJ，不引入额外测试框架。
2. 运行：`mvn -B test`，首次构建需下载依赖，之后单轮约 40 秒。
3. 覆盖率：JaCoCo 0.8.15，绑定 test 阶段，报告输出 target/site/jacoco/index.html，机器可读数据在 target/site/jacoco/jacoco.csv。
4. 本机运行前提：JAVA_HOME 指向 IDEA 自带 JBR 17，即 `E:\env\IntelliJ IDEA 2024.1.7\jbr`；Maven 用 `E:\env\apache-maven-3.8.1`，本地仓库为默认的 C 盘 .m2。

## 三、覆盖率基线
1. 整体：指令 8.0%，分支 4.1%，行 11.6%，即 216/1870 行，全仓 71 个类。
2. 已覆盖重点类：BookingServiceImpl 95.9%，RateLimitService 92.1%，GlobalExceptionHandler 100%，ServiceException 与 RiskBlockedException 100%，EnhanceProperties 100%。
3. 未覆盖集中区：ActivityService 0.8%，CacheService 1.1%，RiskService 2.2%，controller 与 service/admin 两层整体未纳入首轮。
4. 整体比例偏低是因为 71 个类里大部分未纳入首轮，属预期基线，不构成回归信号；核心预约规则与限流链路已在高覆盖区间。

## 四、写法约定
1. 纯单元测试不启动 Spring 上下文，依赖用 @Mock 加 @InjectMocks 注入，保证单轮秒级完成。
2. 规则参数统一走 `getInt(key, default)` 的默认值返回，测试与 rule_config 种子解耦。
3. 涉及 LambdaUpdateWrapper.set 的用例，需在 @BeforeAll 中用 TableInfoHelper.initTableInfo 注册实体，否则纯单测环境拿不到实体元数据，报 can not find lambda cache for this entity。
4. 日期类用例统一取 LocalDate.now().plusDays(1) 构造，避开「当天只能预约当前时刻之后」与自然周滚动带来的时间敏感。
5. MyBatis-Plus 的 BaseMapper 存在 insert(T) 与 insert(Collection) 双重重载，mock 参数要写具体类型，如 any(Booking.class)，写无参 any() 会编译报引用不明确。
6. 新增业务分支时同步补用例，保持 BookingServiceImpl 这类核心类覆盖率不下降。

## 五、后续可选
1. 需要时给 JaCoCo 加 check 规则设行覆盖门槛；当前基线偏低，暂不设卡，避免构建被覆盖率卡住。
2. controller 层可改用 MockMvc 做接口级测试，与现有纯单元测试并行。
3. 并发与端到端验证仍走 tools/bench_concurrency.py 与 tools/demo_test.ps1，单测不重复承担。
