# 房间预约系统：任务分配与阶段计划

状态：2026-09-12 更新。v1 已收口，v1.1 阶段 A 与阶段 B 均已实现并验收，阶段 C 待评估；集成基线为 develop，master 为发布主线。

## 一、阶段划分
1. v1 收口，主线 master，目标中期检查兜底：联调字段补齐、演示稳定、bug 修复、压测基线。
2. v1.1 增强，分支 feature/v1.1-enhance，目标性能与架构亮点，按 A、B、C 三阶段推进，每阶段带开关可降级。
3. 阶段 A：热点数据缓存、索引与连接池调优、接口限流，已完成并验收。
4. 阶段 B：活跃度排行榜与临近取消风控，已完成实现与前后端联调收口，接口清单升 v0.6。
5. 阶段 C：RabbitMQ 事件总线与退约提醒异步化，可靠性增强，验收后评估。
6. 所有增强以配置项控制，Redis 与 MQ 未启动时 v1 主链路必须可运行。

## 二、分工
1. 林义洋，组长：v1 联调字段与 bug 收口，develop 同步维护，接口评审组织与冻结，阶段 A 后端实现（缓存、索引、连接池、限流），压测基线与性能文档，阶段 C 事件总线设计。
2. 刘善宁，用户端：mine 接口 roomName 接入、操作状态与限流提示、排行榜页面与风控 409 提示均已合入 develop；排行榜与风控入口默认由开关关闭。
3. 孙业腾，管理端：管理端页面与统计核对、阶段 A 缓存失效验证已完成；阶段 B 规则参数由通用表格覆盖 18 条，规则页参数编辑组件测试已入库。

## 三、纪律
1. 接口冻结纪律：接口清单 v0.6 为当前版本，v0.5 为阶段 B 冻结基线；契约变更先改文档并标注版本，再改实现。
2. develop 由组长同步：集成验证后推送 origin/develop，组员以 develop 为集成基线。
3. 分支：v1 与 v1.1 已在 develop 集成，master 为发布主线，组员个人分支合入 develop 后同步。
4. 降级：增强依赖不可用时回退原路径，预约创建、冲突检测、退约状态更新始终在数据库事务内同步完成。
5. 每阶段扩展 tools/demo_test.ps1 断言，保证增强不回归。

## 四、阶段 A 任务清单，已完成
1. 后端缓存：琴房列表、琴房详情、规则参数、空闲查询结果，预约与退约后失效相关键。
2. 数据库：booking 与 watch 查询索引核对，慢 SQL 排查。
3. 连接池：HikariCP 最大连接、超时与泄漏检测参数。
4. 限流：单用户预约与关注频次限制，超限返回 429 语义。
5. 前端：缓存命中后的空态与错误提示，提交按钮防抖。
6. 验收：demo_test 扩展缓存失效与限流断言。

## 五、阶段 B 任务清单，已完成
1. 后端计分与排行榜：ActivityService 按事件权重累计分值，Redis ZSET 周月键滚动，不可用时回退进程内，只统计普通用户与会员。
2. 后端风控：RiskService 临近取消判定、计数与临时黑名单，创建预约前强一致拦截并返回 409 与解除时间。
3. 接口：GET /api/rankings/activity 与 GET /api/risk/near-cancel，各按用户每分钟 30 次限流。
4. 前端接入：用户端排行榜页与风控提示，管理端规则页新增九条参数。
5. 验收：脚本加浏览器实测，收口修正四处并升接口清单至 v0.6。
