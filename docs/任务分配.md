# 房间预约系统：并行开发任务分配

状态：2026-09-07，三线并行开工依据。基线 master bcbe7eb。

## 一、分支与协同规则
1. 每人从 master 拉独立 feature 分支，命名 feature/姓名拼音-模块，如 feature/sunyeteng-admin、feature/liushanning-user-web。
2. 每完成一个可验证模块并入 develop 集成，验证后合 master；提交前先 git pull。
3. 提交格式：模块加冒号加内容。
4. 接口契约以 docs/接口清单.md v0.2 为基线，改动契约先更新该文档再同步接口。

## 二、目录边界，防文件冲突
1. docs 与 backend 预约核心既有文件，组长林义洋维护。
2. 孙业腾管理端后端：新建 backend/src/main/java/com/roomreservation/controller/admin 子包；service 层新建 AdminXxxService 独立文件，不得改动既有 ISysUserService、IBookingService 等文件，需要新能力用现有 mapper 自建或提需求给组长。
3. 刘善宁用户端前端：frontend/user-web 独立工程，只动该目录；对后端接口有缺口时列清单交组长补，不直接改 backend。
4. 孙业腾管理端前端：frontend/admin-web 独立工程，只动该目录。
5. 前端统一访问 http://127.0.0.1:9090/api，鉴权请求头 token。

## 三、孙业腾，管理端接口与统计
分支 feature/sunyeteng-admin，目录 controller/admin 与 Admin*Service。
任务清单按接口文档第八至十五节：
1. admin users：用户列表、设会员、重置密码。
2. admin rooms：琴房增删改查，乐器明细整体覆盖。
3. admin bookings：按日期琴房用户状态查询、管理员取消。
4. admin rules：全量读取与批量更新，改后即时生效。
5. admin credit：信用流水、人工减分与恢复，低于阈值停预约逻辑复用组长规则读取。
6. admin feedback：列表与状态处理。
7. admin content：公告与轮播增删改、图片上传。
8. admin stats：首页概览与琴房使用率明细。
9. 所有管理接口方法加 @RequireRole("admin")，登录种子账号 admin/admin123 验证。
验收：接口文档逐节用 Invoke-RestMethod 或 Apifox 冒烟，返回与契约一致。

## 七、v1.1 增强计划：RabbitMQ、Redis 与跨端边界

本节为候选计划，须先完成接口 v0.3 评审、依赖可用性验证和验收脚本设计，再进入实现；在 v0.3 冻结前不开始依赖新接口的正式联调。

1. **林义洋（后端与集成）**：在 `backend` 引入 RabbitMQ/Redis 配置与健康检查；实现事务 outbox（或等价可靠投递）、事件发布、手动 ack/重试/DLQ 和消费者幂等；将退约空出提醒、活跃度计分、临近取消计数与 Redis ZSET/Set 黑名单落地；补充规则参数、候选接口及故障补偿测试。预约写入、冲突检测和信用校验仍保持同步事务。
2. **刘善宁（用户端）**：仅修改 `frontend/user-web`；在首页或独立 `/ranking/activity` 页面接入活跃度排行榜，展示周榜/月榜、本人排名、分数和更新时间；在预约页处理临近取消黑名单的 409，展示解除时间、规则说明和引导；在消息中心沿用现有站内消息接口，处理排行榜最终一致、加载失败、空态和降级提示；预约/退约按钮需防重复提交。不得直接接触 RabbitMQ、Redis 或修改 `backend`。
3. **孙业腾（管理端协作）**：如评审决定开放运营视图，复用规则管理能力配置活动权重、临近窗口、次数阈值与临时限制时长，并按需增加队列/DLQ健康状态或黑名单只读视图；管理接口继续置于 `controller/admin` 并加 `@RequireRole("admin")`，涉及新增接口时先补充契约。
4. **联调与验收**：组长维护 docs 与契约版本；三人共同验证“退约后提醒最终送达、重复事件不重复计分/计数、临近取消达到阈值后拦截且到期解除、RabbitMQ/Redis短暂不可用不影响核心预约”四类场景。所有新增或变更接口先更新 `docs/接口清单.md`。
