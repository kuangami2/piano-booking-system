# 房间预约系统：任务分配与阶段计划

状态：2026-09-08 重构，分 v1 收口与 v1.1 增强两阶段。集成基线 master 849a9c3，develop 同步至此。

## 一、阶段划分
1. v1 收口，主线 master，目标中期检查兜底：联调字段补齐、演示稳定、bug 修复、压测基线。
2. v1.1 增强，分支 feature/v1.1-enhance，目标性能与架构亮点，按 A、B、C 三阶段推进，每阶段带开关可降级。
3. 阶段 A：热点数据缓存、索引与连接池调优、接口限流，中期检查前完成。
4. 阶段 B：活跃度排行榜与临近取消风控，轻量实现，接口已冻结 v0.5，开工。
5. 阶段 C：RabbitMQ 事件总线与退约提醒异步化，可靠性增强，验收后评估。
6. 所有增强以配置项控制，Redis 与 MQ 未启动时 v1 主链路必须可运行。

## 二、分工
1. 林义洋，组长：v1 联调字段与 bug 收口，develop 同步维护，接口评审组织与冻结，阶段 A 后端实现（缓存、索引、连接池、限流），压测基线与性能文档，阶段 C 事件总线设计。
2. 刘善宁，用户端：mine 接口 roomName 已接入并入 develop；参与阶段 B 接口评审；阶段 A 配合缓存空态与提交防抖；阶段 B 排行榜页面与风控提示在接口冻结后实现。
3. 孙业腾，管理端：管理端联调与统计页面数据核对；参与 v0.3 评审；阶段 A 验证缓存失效，管理端改琴房或规则后前端即时更新；阶段 B 风控参数配置页面在接口冻结后实现。

## 三、纪律
1. 接口冻结纪律：接口清单 v0.5 已于 2026-09-10 冻结，阶段 B 按冻结契约实现，后续变更先改文档再实现。
2. develop 由组长同步：master 集成验证后推送 origin/develop，组员以 develop 为集成基线。
3. 分支：v1 修复走 master，v1.1 走 feature/v1.1-enhance，阶段 A 验收前不合主线。
4. 降级：增强依赖不可用时回退原路径，预约创建、冲突检测、退约状态更新始终在数据库事务内同步完成。
5. 每阶段扩展 tools/demo_test.ps1 断言，保证增强不回归。

## 四、阶段 A 任务清单
1. 后端缓存：琴房列表、琴房详情、规则参数、空闲查询结果，预约与退约后失效相关键。
2. 数据库：booking 与 watch 查询索引核对，慢 SQL 排查。
3. 连接池：HikariCP 最大连接、超时与泄漏检测参数。
4. 限流：单用户预约与关注频次限制，超限返回 429 语义。
5. 前端：缓存命中后的空态与错误提示，提交按钮防抖。
6. 验收：demo_test 扩展缓存失效与限流断言。
