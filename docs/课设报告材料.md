## 一、题目与成员
题目：基于 Spring Boot 与 Vue 的琴房预约管理系统设计与实现。
组号 3，成员与分工：林义洋 2023211715 组长，后端预约核心，冲突检测、空出提醒、信用与规则逻辑；刘善宁 2023211716，`frontend/user-web` 用户端页面（后端缺口交组长补）；孙业腾 2023211723，管理端页面及对应后端接口与统计。

## 二、需求概述
面向少房间高自由度的琴房预约。双端 Web 现阶段实现，接口 REST 加 JWT 无状态，为后续微信小程序迁移预留。要点：对内对外琴房与会员权限、全部规则管理端参数化、30 分钟粒度自由选连续时段、冲突即拒绝、退约即释放并触发空出提醒、信用分人工减分与自然恢复、时间自动化推进。详见 docs/需求说明.md。

## 三、技术方案
1. 后端 Spring Boot 3.5 加 MyBatis-Plus 3.5.9 加 MySQL 8，Java 17，以 3+3 脚手架融合管理平台为骨架改造。
2. 鉴权 JWT 无状态，token 请求头，密码 BCrypt，管理接口角色注解拦截。
3. 并发：预约事务内锁琴房行串行化写，再查区间重叠，uk_book_slot 唯一键兜底。
4. 规则参数内存缓存，管理端改参即时生效；定时任务处理预约过期与信用每日恢复。
5. 前端双工程 Vue3 加 Vite 加 Element Plus，用户端与管理端分离，共用接口。
6. v1.1 候选：RabbitMQ 承载退约提醒、活跃度和风控事件；Redis ZSET 维护周期排行榜，Redis Set 维护临时临近取消黑名单；通过 outbox、消费幂等、重试和死信保证可恢复，且不阻断同步预约核心。

## 四、数据库设计
基线 11 张表：sys_user、room、instrument、rule_config、booking、watch、credit_log、feedback、message、notice、banner。对内对外用 room_type，时间窗用当日分钟 open_start 与 open_end，预约与关注存区间并有唯一键防并发与重复。若采用事务 outbox，v1.1 增加 outbox_event 表；ER 物理图采用 dbdiagram，DBML 与 schema 见 docs/schema.sql 与 E:\proc_design_2025_7\doc。

## 五、接口设计
按角色分组共 16 组，用户端实现于 auth、rooms、bookings、watches、messages、feedback、banners、notices、rules；管理端 users、rooms、bookings、rules、credits、content、feedback、stats 待完成。统一 Result 与分页；排行榜与取消风控接口登记为待评审的 v0.3 候选。详见 docs/接口清单.md。

## 六、核心实现说明
1. 预约模块：规则快照校验信用、权限、周次数、时长、提前天数、粒度与冲突，事务内行锁防并发，退约级联触发关注者站内消息。
2. 空出提醒：watch 记录关注时段，退约时按区间重叠找出 active 关注者发消息并置 notified。
3. 信用：初始 100，人工减分低于阈值暂停预约，每日定时自然恢复并记流水。
4. 定时任务：过期预约自动 finished；规则缓存 5 分钟兜底刷新。

## 七、v1.1 候选增强说明（待评审）

预约写入和冲突检测保持 MySQL 同步事务，提交后通过 RabbitMQ 异步处理空出提醒、活跃度计分和临近取消风控。消费者以唯一 eventId 去重，Redis ZSET 使用 `ZINCRBY` 累加周期分数，Redis Set 记录临时黑名单成员并配合用户级 TTL 键；RabbitMQ/Redis 故障时通过 outbox、重试和死信补偿，不影响核心预约。
